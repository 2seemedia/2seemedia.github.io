# لوحة إدارة 2SEE — نسخة اختبار معزولة

الحالة: كود اللوحة يُبنى تلقائياً في Cloudflare من فرع `admin/secure-control-panel` إلى خدمة `2see-admin-staging`. الموقع الرسمي وفرع main لا يتغيران بهذه العملية. النشر الرسمي مقفل لحين الاختبار وموافقة صاحبة الموقع.

## الدخول الحالي

الحساب الوحيد هو **2SEE**، بكلمة مرور مستقلة للوحة. لا يتطلب حساب محمد أو Gmail أو Cloudflare Zero Trust. عيّني كلمة مرور عشوائية طويلة في Worker Secret باسم `ADMIN_PASSWORD` من إعدادات خدمة الاختبار. يجب أن يكون طولها بين 24 و256 محرفاً؛ لا تعيدي استخدام كلمة مرور Gmail أو Cloudflare، ولا تضيفيها إلى المستودع أو الدردشة. لا توجد كلمة مرور افتراضية.

الجلسة موقّعة ومحددة بنطاق الخدمة، ومدتها أربع ساعات. الكوكي Secure / HttpOnly / SameSite=Strict ويستخدم بادئة __Host-. تغيير ADMIN_PASSWORD يبطل الجلسات السابقة. تسجيل الخروج يمسح جلسة المتصفح؛ النسخة المسروقة من الكوكي تظل صالحة حتى انتهائها أو تغيير كلمة المرور. لا نخزن كلمات مرور أو جلسات في localStorage. المسودات المحلية تظل محفوظة للمستخدم نفسه.

حد محاولات الدخول: 5 طلبات لكل عنوان IP بالدقيقة و20 طلباً إجمالاً بالدقيقة في كل مركز Cloudflare. هذه الحدود محلية لكل مركز وليست قفلاً عالمياً موزعاً، لذلك يلزم استخدام كلمة مرور عشوائية قوية. عدم تهيئة كلمة المرور أو روابط تقييد المحاولات يمنع تسجيل الدخول بالكامل. طلبات تسجيل الدخول والخروج والنشر تتحقق من Origin وترويسة خاصة؛ كل ملفات اللوحة والمعاينة محمية بالجلسة، عدا صفحة الدخول وملفها البرمجي.

يبقى كود Cloudflare Access السابق متاحاً كخيار تقني منفصل عند AUTH_MODE=access، لكن إعداد الاختبار الحالي يستعمل AUTH_MODE=password ولا يرجع تلقائياً إلى Access عند حدوث خطأ.

## التشغيل والتحقق

```bash
npm ci
npm test
npm run build
npx wrangler deploy --dry-run
```

من مجلد secure-admin. البناء يجمع صفحات الموقع وأصوله الأصلية من جذر المستودع، مع واجهة الإدارة الخاصة؛ لا ينشر public/ إلى GitHub Pages.

للمعاينة المحلية ببيانات عامة فقط: `node tests/preview-server.mjs` ثم `http://127.0.0.1:8789`. هذه واجهة اختبار بلا تسجيل دخول والنشر فيها معطل؛ لا تدخل حزمة Worker ولا تثبت أمان المصادقة. اختبارات DOM ليست اختبار متصفح بصرياً.

## إعداد GitHub

قراءة المحتوى من المستودع العام تعمل بدون رمز GitHub ضمن حدود API العامة. للنشر وحماية القراءة من حدود الطلبات المنخفضة، أضيفي Worker Secret باسم `GITHUB_TOKEN`، باستخدام Fine-grained token بصلاحية Contents Read/Write لهذا المستودع فقط. إدخال الرمز يتم مباشرة في واجهة Cloudflare؛ لا يُوضع في الكود أو الدردشة أو المتصفح كحقل نشر.

الفرع المستهدف للنشر التجريبي هو `admin/content-staging`، وليس main. النشر مفعّل على فرع الاختبار فقط عبر PUBLISH_ENABLED=true، وتبقى PRODUCTION_APPROVED=false في إعداد الاختبار. لا توجد موافقة حالية على النشر الرسمي.

## آلية النشر

تُجمع الصور وملفات محتوى JS وJSON في commit واحد. تحديث الفرع force=false يرفض التعارض بدلاً من استبدال تغيير أحدث. المسودة تحفظ معرّف المحتوى الذي بدأت منه، حتى بعد إعادة فتح المتصفح. تُسجّل عمليات حساب اللوحة المشترك باسم 2SEE؛ لا يمكن تمييز من المؤسسين استعمل الحساب نفسه.

نجاح commit لا يؤكد نجاح GitHub Pages؛ بعد السماح بالنشر الرسمي يلزم التحقق من البناء والموقع. التراجع يكون عبر revert للـcommit بعد مراجعة التغييرات الأحدث؛ لا يوجد زر تراجع آلي. الصور الجديدة تُقرأ من فرع المحتوى عند عدم وجودها في حزمة Worker، دون إعادة نشر اللوحة.

## ميزات الواجهة وحدودها

تحتفظ الواجهة بالمحرر المرئي الحالي، والنصوص العربية والإنجليزية، وأغلفة وروابط الريلز، والأعمال، والشعارات، والألوان والخطوط وتنسيق العناصر وإظهار الأقسام. المسودات محلية لكل متصفح ويمكن تصديرها. لا يوجد تحرير تعاوني لحظي أو رفع فيديو خام؛ إضافة نوع قسم جديد تحتاج تطويراً.

## مراجعة الإنتاج — بانتظار موافقة صاحبة الموقع

نجحت تجارب الدخول والمعاينة العربية والإنجليزية والمحرر المرئي والنشر التجريبي للصور والاستعادة. الأدلة والحدود موثّقة في [QA.md](QA.md).

- ضبط كلمة مرور اللوحة واختبار دخول حقيقي ورفض كلمة مرور خاطئة والخروج وانتهاء الجلسة.
- اختبار المعاينة بالعربية والإنجليزية وعلى الموبايل والكمبيوتر، وتأكيد تطابق الهوية الحالية.
- ضبط GitHub Secret ثم تفعيل النشر على فرع الاختبار فقط، واختبار الصور والتعارض وثبات main.
- موافقة صاحبة الموقع على النسخة المجربة قبل تهيئة الخدمة الرسمية أو تعديل اللوحة العامة القديمة.
