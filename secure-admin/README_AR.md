# لوحة إدارة 2SEE — نسخة مراجعة معزولة

الحالة: تنفيذ وتجارب محلية ناجحة؛ لم تُنشر على Cloudflare، ولم تتغيّر ملفات الموقع العام أو فرع main. لا تعتبر هذه النسخة معتمدة للإنتاج قبل الاختبار الفعلي وموافقة إسراء.

## التصميم والمحتوى

تعتمد النسخة على المستودع الحالي عند commit `aaa376f901e8a6296f70f8c89670972a8e0ebad4`، لأن محرره المرئي أحدث من المرفق V15. يحتفظ البناء بصفحات الموقع وCSS والصور كما هي. التغييرات محصورة داخل secure-admin. الواجهة تدير النصوص العربية والإنجليزية، الصور، روابط الريلز، الأعمال، الشعارات، الألوان، الخطوط، تنسيق العناصر وإظهار الأقسام.

## التشغيل والتجارب

من مجلد secure-admin:

```bash
npm ci
npm test
npm run build
npx wrangler deploy --dry-run
```

اختبارات Node تتحقق من توقيع JWT والجمهور والصلاحية وقائمة المؤسسين، وحماية الأصول وطلبات النشر، والتعارض، والنشر الذري، وحد حجم الطلب، وبنية البيانات. اختبارات DOM تتحقق من تحميل جميع تبويبات اللوحة، وتعديل الهوية، وحفظ المسودة ومعاينتها، وحماية المسودة القديمة وإضافة الأعمال. اختبارات DOM ليست اختباراً بصرياً بمتصفح حقيقي.

للمعاينة المحلية ببيانات عامة فقط: `node tests/preview-server.mjs` ثم افتحي `http://127.0.0.1:8789`. هذه واجهة اختبار بلا تسجيل دخول والنشر فيها معطّل دائماً؛ ملفها لا يدخل حزمة Worker. لا تُستخدم لاختبار أمان المصادقة.

## ما يلزم لإكمال ربط Cloudflare

1. تسجيل الدخول وفحص إعدادات الخدمة الحالية `2see-admin-api` دون استبدالها. حفظ إصدارها وإعداداتها الحالية قبل أي تغيير.
2. استخدام خدمة اختبار منفصلة `2see-admin-staging` وفرع المحتوى `admin/content-staging`؛ يبقى main كما هو. لا تكفي نسخة هذا المجلد وحدها: البناء يجلب صفحات الموقع وأصوله من جذر المستودع.
3. إنشاء تطبيق Cloudflare Access يغطي نطاق خدمة الاختبار كاملاً، وإضافة إيميلي إسراء ومحمد الفعليين فقط. اعتماد رمز بريد لمرة واحدة أو موفر هوية موجود، ومنع سياسة Bypass. يلزم تأكيد هويتي الحسابين قبل تفعيل الوصول.
4. ضبط ACCESS_TEAM_DOMAIN وACCESS_AUD وALLOWED_EMAILS. المتغيرات الحالية placeholders تمنع كل وصول. run_worker_first=true يلزم حتى تمر جميع الملفات على التحقق من JWT.
5. تخزين GITHUB_TOKEN كـ Worker Secret فقط. صلاحية Fine-grained Contents Read/Write لهذا المستودع وحده. لا يُضاف الرمز إلى الملفات أو الدردشة أو المتصفح. إدخال الأسرار خطوة يقوم بها صاحب الحساب بواجهة Cloudflare الآمنة عند الحاجة.
6. نشر خدمة الاختبار بعد ربط Access والتحقق من رفض الطلبات المجهولة. تفعيل PUBLISH_ENABLED=true في الاختبار فقط، مع GITHUB_BRANCH=admin/content-staging وPRODUCTION_APPROVED=false.

## اختبار القبول قبل الإنتاج

- دخول كل مؤسس بإيميله الفعلي؛ رفض إيميل ثالث ورفض JWT غير صالح على كل المسارات، بما فيها ملفات JavaScript وصفحات المعاينة.
- تعديل نص عربي وإنجليزي، لون، خط، صورة، شعار، ريل وقسم، ثم معاينتها على الكمبيوتر والموبايل. فحص تطابق الهوية مع الموقع الحالي.
- النشر التجريبي وتأكيد ظهور الصور الجديدة بعد إعادة فتح المعاينة، وتأكيد ثبات main.
- فتح مسودتين للمؤسسين؛ نشر الأولى ثم التحقق من رفض الثانية برسالة تعارض دون خسارة تعديل الأولى.
- فحص JWT حقيقي وتهيئة Access والأسرار على Cloudflare، وليس الاكتفاء بمحاكاة الاختبارات المحلية.
- موافقة إسراء على النسخة المجربة، ثم إعداد الخدمة الحالية للنشر الرسمي. يبقى هذا الإجراء مؤجلاً؛ إعداد الاختبار لا يشير إلى main.
- بعد الموافقة فقط: إزالة حقول رمز GitHub من اللوحة العامة القديمة أو تحويل رابطها للوحة الجديدة، وتفعيل الخدمة الرسمية مع PRODUCTION_APPROVED=true وGITHUB_BRANCH=main، والتحقق من نجاح GitHub Pages بعد أول نشر. الإعداد الافتراضي لا يفعّل هذا المسار.

## النشر والاسترجاع

الصور والمحتوى JS وJSON تُجمع في Git tree واحد ثم commit واحد. تحديث الفرع يستعمل force=false، فيرفض تغييراً متزامناً بدلاً من الكتابة فوقه. لا يرى الموقع أي كتابة جزئية إذا فشل إعداد الصور. المسودة تحتفظ بمعرّف نسخة المحتوى التي بدأت منها؛ فتح اللوحة من جديد لا يلغي كشف التعارض.

نجاح GitHub commit لا يثبت اكتمال GitHub Pages. تعرض الواجهة ذلك صراحة؛ يلزم فحص البناء والموقع بعد النشر الرسمي. سجل GitHub يحفظ صاحب عملية النشر والتاريخ ومعرّفها. للتراجع: إنشاء revert للـcommit المطلوب، مع مراجعة التغييرات الأحدث قبل اعتماده. لا يوجد زر استرجاع آلي في هذه النسخة.

المسودات محلية لكل جهاز/متصفح، ويمكن تصديرها واستيرادها. لا يوجد تحرير تعاوني لحظي أو رفع ملفات الفيديو الخام؛ الريلز تُدار بروابطها وأغلفتها. أقسام قالب الموقع قابلة للإظهار والإخفاء، وإضافة نوع قسم جديد تحتاج تطويراً. لا تُحذف الوسائط تلقائياً من Git حتى لا تنكسر روابط نسخ سابقة.
